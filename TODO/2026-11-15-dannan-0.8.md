# Lugh on Dannan 0.8.0 (plan, 2026-11-15)

Dannan 0.8.0 is tagged (6c240cc): `dannan::listen` (the public listener, with Lugh's review in it), `sched::WorkerPool` and
`ClassGate`, sealed counters, `Budget::acquire`, `dannan-custody`, and `DANNAN_BUILD_TOOLS`. The maintainer paused Lugh after P10 "until
Dagda or Dannan 0.8.0 unblocks P8 and the listener move" (2026-11-14).

## Step 1, the pin (done when green)

`LUGH_DANNAN_REF` 0.8.0, `DANNAN_BUILD_TOOLS` OFF where Lugh fetches Dannan. Lugh has no `Nodes` double, so the new pure virtuals
(`watch_advert`, `unwatch_advert`) touch nothing; no `find_package(dannan)` minimum to raise. One debug run on a build node.

## Step 2, the listeners onto `dannan::listen` (the maintainer, 2026-11-15: start it)

Found first (2026-11-15), sent to Dannan: `StreamListener::stop_accepting()` posts to the acceptor's strand and blocks on the
result, so called from a handler on a one-thread io_context (Lugh's SIGTERM handler) or after `run()` has returned, it hangs.
Asked for an inline close on the running thread, or an asynchronous `stop(executor, done)`. Fixed for Dannan 0.8.1
(`feature/no-delay`; reviewed by Lugh, one non-blocking note: an io_context that never ran waits the 5 s bound). The move ships on
0.8.1, which also sets TCP_NODELAY on every accepted socket.

On `feature/dannan-listen`, in steps each green on a build node: (A) HTTP: `HttpServer` keeps its face (`middleware_add`, `listen`, `start`,
`stop`, `port`) and serves over a `StreamListener`, taking a `listen::Certificates` in place of an `ssl::context`; (B) LDAP:
`LdapServer` likewise, StartTLS through `Stream::start_tls`; (C) `lugh-node`: one `Certificates` per listener's files, reloaded on
SIGHUP, sockets inherited by name when systemd passes them; (D) `TlsContext` deleted (C done 2026-11-15: certificates reloaded on SIGHUP, `ExecReload` in the unit, a process test;
socket activation left for later, since `inherited_socket` checks LISTEN_PID against the child's pid, which a test cannot set
before it starts, and Lugh does not ship what it cannot test), its tests' removal recorded with the reason in
`COMPLETED.md`; (E) `ClientAddress` on `forwarded_for()` and prefixes.

What moves: `lugh/http/http_server` (the HTTPS listener and the mTLS one) and `lugh/ldap/ldap_server` (LDAP with StartTLS on 389,
LDAPS on 636) accept through `StreamListener`, each connection a `listen::Stream` under Beast or Lugh's BER reader.

- **TLS**: `listen::Certificates` (the operator's chain, key and client CA, reloaded on SIGHUP), `TlsPolicy` per listener: HTTPS
  TLS 1.3, ALPN http/1.1, client certificates never; mTLS optional; LDAPS and StartTLS 1.2 (old clients).
- **Client certificates**: `Stream::client_certificate()` (thumbprint as 32 bytes, base64url-encoded for `cnf.x5t#S256`, subject,
  verdict) replaces the headers `http_server` sets today (`Lugh-Client-Cert-*`), which the routes read through
  `http::client_certificate`; that seam stays, fed from the stream.
- **StartTLS**: Lugh hands `start_tls` its encoded ExtendedResponse; with operations outstanding it answers operationsError first
  (RFC 4511 4.14.1), so `send()` never holds bytes then.
- **Limits**: Lugh's per-request `RateLimiter` stays; `listen::Limits` only as a backstop, off by default, trusted proxies by prefix
  (from `http.trusted_proxies`); `forwarded_for()` replaces `ClientAddress`'s walk of X-Forwarded-For.
- **Deadlines and close**: the handshake, idle and outbound bounds from the listener; a close cancels a pending read with
  `operation_aborted`, which the readers take as the end.
- **Binding**: `inherited_socket("https")`, `("ldap")`, `("ldaps")` from systemd socket activation when the unit passes them,
  else bind; the unit file gains the sockets.
- Deleted afterwards: `TlsContext`, the accept loops, and `ClientAddress`'s header walk, if nothing else uses them.
- Tests: the HTTP, LDAP and process tests are the proof; they must pass unchanged in count, with new ones for SIGHUP reload and
  socket activation.

## Step 3, hashing on `sched::WorkerPool` (at P8.1)

Today Argon2id runs on a `boost::asio::thread_pool` of `kHashingThreads` through `on_pool`, whose queue has no bound. The
agreed shape (needs document, N6): Lugh's own `WorkerPool` (2 threads, foreground, a small queue), each hash's memory reserved
with `Budget` before submit, refused at once when full ("try again shortly": HTTP 503 with Retry-After, LDAP busy). The pool takes
the node's `ClassGates` and `SupervisedThreads`, and `Budget` is the node's: all from Dannan's `Context`, which Lugh has from
P8.1 (lugh-node a Dannan node). Recommended: at P8.1, not before; until then the unbounded queue is a known gap, stated here.
