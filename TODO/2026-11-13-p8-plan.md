# P8: Lugh on Dannan and Dagda

The plan for Lugh's move onto the stack (stack document, `../dagda/TODO/2026-11-03-stack.md`, "What changes for Lugh"),
against Dagda's slices as the maintainer ruled them on 2026-11-13 (`../dagda/TODO/2026-11-13-three-systems-design.md`, "Ruled") and
Lugh's needs of the two libraries (`2026-11-13-lugh-needs-of-the-stack.md`). Each step is a commit with its tests; each ends green
under ASan with UBSan and under TSan, repeated and shuffled, as `CLAUDE.md` says.

Each statement is **Settled** (the maintainer's, with where) or **Proposed** (for the maintainer).

## Where Lugh is

Everything Lugh persists goes through one interface, `lugh/store/store.h`: named tables with unique indexes; `get`, `find` by
index, `list`; `put` and `remove` conditional on a version (0: must not exist), a removal final and its key never reused. Under
it sits the interim sealed store (`lugh/store/`) and keyring (`lugh/keys/`), frozen and marked for deletion (the maintainer: "Keep the
store until Dagda"). `lugh/test/store_contract_test.cpp` states the interface's contract, and `MemoryStore` is the tests' copy.
State held only in memory today: authorisation codes, PAR URIs and waiting requests, device grants, the `private_key_jwt`
replay cache, DPoP proof `jti`s, revoked access-token `jti`s, opaque-token handles (all `Expiring<T>`), sessions' in-memory
copy, back-channel logouts waiting, and the sign-in back-off (`Backoff`, per node).

## The approach (Settled: the maintainer, 2026-11-13)

Each component is rewritten against Dagda's spaces directly: Directory, Passwords, Factors, AppPasswords, EnrolmentLinks,
Policies, Grants, Apps, Consents, SigningKeys, Sessions, RefreshTokens, the POSIX numbers, the audit log and OAuth's short-lived
state. `store::Store`, its table and index model, `MemoryStore` and `store_contract_test` go, with the sealed store and keyring.
A component's record is a key in a space, its codec Lugh's, its derived indexes Lugh's own in memory, its conditional write a
`Context::Heads::mutate`. The tests stay as the guard: each component's tests are written from the design, not from the old store,
and run on Dagda's installed fixture (one node for a component's own behaviour, two or three for what a cluster changes), so a
component moves when its suite passes there.

A record's key in a space is `<kind>/<id>`; its value is Lugh's existing record bytes, so every codec stays. Lugh's version
field (Settled: stack Decided 17, ETags) is in the value, and a conditional write is a `Context::Heads::mutate` whose mutation
checks the version in the view it is handed and refuses with `conflict`.

## The merge (Settled: the maintainer, 2026-11-13)

One merge for `lugh/scope` and `lugh/secrets`, over the record map, given the common ancestor (Dagda's `Merge::merge(base,
heads)`):

- A key changed on one side only: that side.
- A key changed on both: the higher version, then the higher writing node's id, deterministically. Credentials are versioned,
  so the newer credential wins.
- A removal on either side wins over any edit: tombstones are kept for ever and a removed key is never written again (Settled:
  stack Decided 16; the store contract's "removal is final").
- Unique indexes: two live records with one index value (two `alice`s made in a split) are both kept, and the index marks the
  value ambiguous. Sign-in and LDAP bind by an ambiguous name are refused until an administrator renames one (Settled: stack
  requirement e). Tokens carry the immutable id, so OAuth is unaffected.

## Derived indexes and caches

Every index and the in-memory copy of sessions follow `Heads::watch` and `Heads::changed` (slice 1): a change on any node
reaches every other node's memory as fast as the commit does. Slice 0 measures that latency for Lugh's shape; it replaces the
session refresh's one-minute poll (the maintainer confirmed the minute as built; the notice makes it seconds, without a change of rule).

## P8.1, settled (the maintainer, 2026-11-24)

P8.1 is `lugh-node` on Dannan 0.12.0's node-program helper (`supervise::run_node_program`), which makes it a Dannan node.
1. **Where P8 lives**: a long-lived `feature/p8` branch off `develop`, with `develop` merged into it after each change there (never rebased: it is pushed, and nothing is force-pushed), from P8.1 on. `develop` keeps
   releasing 0.x for the dependants meanwhile; `feature/p8` merges into `develop` when v2 is frozen.
2. **Settings**: Lugh takes the helper's names, without aliases, as 0.4.0 did: a listener's `https.listen.address`,
   `https.listen.port`, `https.tls.certificate`, `https.tls.key` (`ldap.*` the same shape), and `log.*`, `node.*` and
   `cluster.*`. The old names go, with a table in `CHANGELOG.md`; neptune's configuration and the package's conffile change
   with them.
3. **One node**: a `lugh-node` with no `cluster.*` is a cluster of one, its identity in its state directory; more nodes are
   a configuration change. Today's installs keep working.
4. **The keyring**: `lugh-node init` makes the node's custody. At the first start after the upgrade, an existing keyring's
   master key is re-wrapped once under a key custody derives (`lugh/keyring`), the old sealed file kept as a backup until
   the next release; from then on there is one root to unseal. The keyring itself goes at P8.8.

## Acknowledgement levels, named (the maintainer, 2026-11-15, a group standard via Kvasir)

The stack names how sure a write is, not numbers: `ephemeral` (the node answers at once), `persisted` (its own disk has it),
`decided` (a majority agreed it), `replicated` (a majority of the replicas have it on disk); the setting is `ack_level`
(`../kvasir/TODO/2026-11-15-ack-levels-standard.md`). Dagda's durability levels named in this plan (Ephemeral, Persisted, Replicated
on k nodes, Durable on every replica) do not map one to one onto it. At P8, Lugh uses whatever names Dagda's contract then exposes,
and its own logs, Status and docs follow the standard. Where Dagda's names differ, that is settled with Dagda first.

## What a cluster changes, stated

- **The partition bound** (Settled: stack d): a disabled account or revoked session is honoured on the other side of a split until
  it heals.
- **TOTP and recovery codes fail closed** on a side that cannot reach a majority of their register's replicas (the maintainer, 2026-11-13;
  the register replaces the lease, the maintainer 2026-11-15).
- **A node newly advertising `lugh`** cannot open `lugh/secrets` until configuration names it a member, until Dagda's catalogue
  (slice 5); sign-in fails on that node until then.
- **Duplicate names** from a split are refused at sign-in until renamed.
- **A node on the minority side** (Dannan's partition reading) reports it in Status and the audit log and keeps serving (the maintainer,
  2026-11-14).
- **Joining a node during a split** can give both sides a majority reading (the maintainer kept Dannan's rule as built, 2026-11-14), so a
  new Lugh node is joined only to a whole cluster; the operator documentation says so.

## Decided (the maintainer, 2026-11-13)

1. Each component rewritten against Dagda's spaces, not `store::Store` over Dagda.
2. The merge as above: higher version then node id for edits, removal over edit and never resurrected, duplicate names both kept
   and refused at sign-in and bind until renamed.
3. The back-off counter in its own every-node space.
