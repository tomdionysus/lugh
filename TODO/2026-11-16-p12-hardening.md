# P12: hardening

The maintainer, 2026-11-16: P12 after P7. The phase as `ACTIVE.md` had it: fuzzing campaigns (every target built first), a sandbox review,
key rotation drills, and a threat model.

## What constrains it

- **ASan.** Every fuzz target is built `-fsanitize=fuzzer,address,undefined`. ASan could not start on the build nodes' first 4K-page
  kernels (39-bit VMA); since 2026-11-16 every build node runs a 4K-page, 48-bit-VA kernel and ASan and TSan both run.
- **No builds on the Mac.** libFuzzer is clang's: clang 19 on node-b, node-a and node-c.
- **The store and keyring are frozen** until P8; hardening them means tests and fuzzing, not changes, unless something is found.

## As done

- **The test installs** (H3): on each build node a release `lugh-node` installed by `cmake --install`, its own genesis, the master key
  sealed by `systemd-creds` (no TPM: the host key), root's password in `/root/lugh-root-password` (0600, root only), the service
  enabled on 443. Each is a single node until P8 makes them one cluster. On every build node: `systemd-analyze security` 1.4 (OK), health
  200, `LoadCredentialEncrypted=` opening the store, `LimitMEMLOCK` 16 MiB with 140 kB of key memory locked, 36 mappings
  `MADV_DONTDUMP`, cores off.
- **Found by the installs**: GCC 14's release build took an optional for maybe uninitialized (rewritten); the install never ran
  `ldconfig`, so `lugh-node` could not find Dannan's library on a clean host (it does now).
- **Found by fuzzing**: `encode_topic` wrote `"` and `\` literally in a level, making a scope that was no scope (fixed); `fuzz_records`
  held an old-format record to its bytes (its property fixed); and `__builtin_trap()` raises SIGTRAP on arm64, which libFuzzer does
  not catch, so a find left no input (the targets abort now). The libFuzzer check had never passed, so no target had built.
- **The hour-long campaign** (2026-11-16/17, node-c): twelve targets an hour each, about 3.4 billion inputs, nothing found.
  `fuzz_webauthn` ran out of its 2 GiB after 98 million runs, and that led to a real bound: a CBOR array or map header could make
  a Value for every claimed item before reading one, at every level, so a few kilobytes made tens of megabytes. A count is now
  held to the items still allowed (fixed, with a test).
- **Found 2026-11-17, after the campaigns**: the fuzz build instrumented only each target's own file. `liblugh` and Dannan were
  built with no `-fsanitize` flag at all, so libFuzzer saw no edge inside a parser (no coverage to steer by, the corpus grew only
  on the harness's few branches) and ASan and UBSan checked none of the parsers' reads, only the allocator's calls. The 3.4 billion
  inputs were close to blind mutation: they proved the targets' properties held and nothing crashed outright, not that a parser
  reads within its bounds. Fixed in the build: with `LUGH_BUILD_FUZZING` every object, Dannan's too, is built
  `-fsanitize=fuzzer-no-link,address,undefined` (`LUGH_FUZZ_SANITIZERS` OFF leaves libFuzzer alone, for measuring). The
  campaigns are run again on it before Lugh's first release (the maintainer, 2026-11-17: "We don't need these until a release").
- **Closed 2026-11-17, the RSS**: built with libFuzzer alone (`LUGH_FUZZ_SANITIZERS=OFF`, every object instrumented),
  `fuzz_webauthn` held 43 MiB peak for 14.3 million runs in ten minutes, its corpus still growing. The climb below was ASan's
  allocator, not Lugh's.
- **Found 2026-11-17, a parser never fuzzed**: `fuzz_webauthn` read only CBOR and COSE keys; `parse_authenticator_data` and
  `es256_raw_signature` (both of the browser's bytes) had no target. They are in it now, with their stated properties
  (attested data exactly when its flag is set, backed up never without backup-eligible, a converted signature from at most 72
  bytes): a minute, libFuzzer alone, 2 million runs, nothing found, coverage 315 to 393 edges.
- **Binary seeds** (`lugh/fuzz/seeds.sh`, which computes every length): `ber` (bind, anonymous and simple; search, with and
  without the paged-results control; password modify; unbind), `filter` (equality, and, or with not, substring, greater or
  equal), `webauthn` (COSE ES256 and RS256 keys, `none` attestation objects with each, authenticator data for registration and
  assertion, a DER signature). Each checked against the parsers: all accepted as meant. Not seeded: the frozen store's formats
  (`keyring`, `store_log`, `records`, `envelope`), which P8 replaces; coverage now steers their targets regardless.
